# e-Aduan Smart Management System

A government-grade public complaint management platform where residents submit, track, and resolve issues — and admins manage everything from a single dashboard.

---

## Features

| Audience | Capabilities |
|---|---|
| **Public** | Track any complaint by ticket ID — no login required |
| **Residents** | Register, submit complaints (category, priority, location, image), view history, check admin comments, update profile |
| **Admins** | Full complaint management (filter, update status, delete), user management (promote/demote, ban/unban), analytics dashboard with charts |

---

## Tech Stack

- **Frontend**: React 19 + Vite, shadcn/ui, Tailwind CSS v4, TanStack Query, Wouter
- **API**: Express 5, JWT auth, Helmet, express-rate-limit
- **Database**: PostgreSQL + Drizzle ORM
- **Monorepo**: pnpm workspaces, Node.js 24, TypeScript 5.9
- **Validation**: Zod v4 + drizzle-zod
- **API contract**: OpenAPI spec → Orval codegen (React Query hooks + Zod schemas)

## Deploying to Render.com

This project ships with a `render.yaml` that defines everything Render needs: two services and a PostgreSQL database.

### What gets deployed

| Service | Type | Description |
|---|---|---|
| `eaduan-api` | Node.js Web Service | Express API (`/api/*`), port 10000 |
| `eaduan-web` | Static Site | React SPA, served from CDN |
| `eaduan-db` | PostgreSQL | Managed database, free tier |

### Step-by-step

#### 1. Push the repo to GitHub

```bash
git remote add origin https://github.com/<you>/e-aduan.git
git push -u origin main
```

#### 2. Create a new Render Blueprint

1. Go to [dashboard.render.com](https://dashboard.render.com) → **New → Blueprint**
2. Connect your GitHub account and select the repository
3. Render will detect `render.yaml` and create all three resources automatically
4. Click **Apply**

#### 3. Wait for the first deploy

Render will:
- Install dependencies (`pnpm install --frozen-lockfile`)
- Build the TypeScript libs (`pnpm run typecheck:libs`)
- Bundle the API with esbuild
- Push the database schema (`drizzle-kit push --force`)
- Build the frontend with Vite
- Deploy both services

The first deploy takes 3–5 minutes.

#### 4. Wire up the two service URLs (one-time step)

Because the API and frontend are separate services, you need to tell each one where the other lives:

**a) Copy the API URL**

In the Render dashboard, open the `eaduan-api` service → copy its URL, e.g.:
```
https://eaduan-api.onrender.com
```

Open the `eaduan-web` service → **Environment** → set:
```
VITE_API_URL = https://eaduan-api.onrender.com
```
Click **Save changes** and trigger a manual redeploy of `eaduan-web`.

**b) Copy the frontend URL**

Open the `eaduan-web` service → copy its URL, e.g.:
```
https://eaduan-web.onrender.com
```

Open the `eaduan-api` service → **Environment** → set:
```
ALLOWED_ORIGINS = https://eaduan-web.onrender.com
```
Click **Save changes** (the API redeploys automatically).

> If you attach a **custom domain** to either service, add it to the respective variable as well (comma-separate multiple values in `ALLOWED_ORIGINS`).

#### 5. Verify the deployment

```bash
# Health check
curl https://eaduan-api.onrender.com/api/healthz
# Expected: {"status":"ok"}

# Open the frontend
open https://eaduan-web.onrender.com
```

Log in with the demo credentials above to confirm everything works end-to-end.

### Environment variables reference

#### `eaduan-api` (API Web Service)

| Variable | Source | Description |
|---|---|---|
| `NODE_ENV` | `production` | Enables production mode |
| `PORT` | `10000` | Port the Express server binds to |
| `DATABASE_URL` | Auto-injected from `eaduan-db` | PostgreSQL connection string |
| `SESSION_SECRET` | Auto-generated by Render | JWT signing secret (keep secret) |
| `ALLOWED_ORIGINS` | Set manually | Comma-separated list of frontend URLs allowed by CORS |

#### `eaduan-web` (Static Site)

| Variable | Source | Description |
|---|---|---|
| `NODE_ENV` | `production` | Passed to Vite at build time |
| `VITE_API_URL` | Set manually | Absolute URL of the API service (baked into the bundle) |

### Database migrations

Schema changes are applied automatically on each deploy via `drizzle-kit push --force` in the API build command. For destructive changes (column drops, renames), review the diff locally first:

```bash
pnpm --filter @workspace/db run push
```

---

### Updating after code changes

Push to the `main` branch — Render auto-deploys both services. No manual steps needed unless you change the API URL or frontend URL.

## Local Development (Replit)

Everything runs automatically in Replit. Use the demo credentials above.

### Useful commands

```bash
# Full typecheck
pnpm run typecheck

# Regenerate API hooks after changing openapi.yaml
pnpm --filter @workspace/api-spec run codegen

# Push schema changes to the local database
pnpm --filter @workspace/db run push
```

## Project Structure

```
artifacts/
  api-server/       Express API (bundles to dist/index.mjs via esbuild)

lib/

  api-zod/          Generated Zod schemas
  api-client-react/ Generated React Query hooks + custom fetch
  db/               Drizzle ORM schema + migrations

```
